#### ⚠️ SEGURANÇA EM VIBE CODING

> [!CAUTION]
> **TEMA CRÍTICO - A falta de segurança em aplicações construídas via Vibe Coding é uma EPIDEMIA**
> 
> Milhares de SaaS e aplicações estão sendo hackeados diariamente, expondo:
> - Dados pessoais (nome, CPF, endereço, telefone)
> - Informações financeiras (cartões de crédito, transações)
> - Dados sensíveis de clientes
> - Credenciais e tokens de acesso

##### Vulnerabilidades Comuns em Vibe Coding

1. **Ausência de Row Level Security (RLS)**
   - Tabelas abertas para qualquer usuário autenticado
   - Exposição de dados de todos os clientes
   - Solução: Implementar RLS obrigatoriamente

2. **API Keys expostas no frontend**
   - Chaves de API hardcoded no código cliente
   - Service role keys acessíveis publicamente
   - Solução: Usar Edge Functions e variáveis de ambiente

3. **Falta de validação de input**
   - SQL Injection
   - XSS (Cross-Site Scripting)
   - Solução: Sanitização e validação server-side

4. **Autenticação mal implementada**
   - Tokens não verificados
   - Sessions sem expiração
   - Solução: Usar Auth providers confiáveis (Supabase Auth, Clerk)

5. **Permissões excessivas**
   - Usuários com acesso a dados que não deveriam
   - Admin panels sem proteção adequada
   - Solução: Implementar RBAC rigoroso

6. **Buckets de Storage públicos**
   - Arquivos sensíveis acessíveis publicamente
   - URLs previsíveis
   - Solução: Buckets privados + políticas de acesso

7. **Logging e exposição de dados sensíveis**
   - console.log com dados de usuários
   - Errors expondo stack traces
   - Solução: Logging adequado e error handling

##### Checklist de Segurança Obrigatório

```markdown
□ RLS ativado em TODAS as tabelas com dados sensíveis
□ API keys armazenadas em variáveis de ambiente
□ Validação de input em todos os formulários
□ Autenticação via provider confiável
□ RBAC implementado corretamente
□ Storage buckets com políticas adequadas
□ HTTPS forçado em produção
□ Rate limiting implementado
□ Logs sanitizados (sem dados sensíveis)
□ Backup e disaster recovery configurados
□ Penetration testing antes do launch
```
